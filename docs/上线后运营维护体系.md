# 上线后运营维护体系

> 生成于 2026-10-08。所有数字来自逐行读码与实测，标注「估算」的部分给出推算依据。
> 本文回答一个问题：**用户变多之后，会发生什么、提前做什么、出事了怎么办。**

---

## 一、先说结论：三个会最先出问题的地方

按「多快会发生」排序：

| # | 问题 | 触发条件 | 后果 | 状态 |
|---|---|---|---|---|
| 1 | **数据库没有索引** | 单集合超过几千行 | 查询变慢 + **费用随行数线性上涨**（云开发按读取次数计费，无索引=全表扫描） | ⏳ **只能在控制台手工建**（见第三节） |
| 2 | **照片是原图，无压缩** | 几十个活跃项目 | 存储与流量成本快速上涨；报告每被查看一次就重新下载全部原图 | ✅ **已完成**（见第四节） |
| 3 | **AI / ASR 按量计费** | 用户开始用 AI 识图 | 费用与调用量同比例增长，且没有限额保护 | ✅ **已完成**（见第六节） |

**索引为什么不能由代码建**：已确认 `wx-server-sdk` **连最新版 4.0.2 都不支持**
`createIndex`，只暴露 `createCollection`。管理端接口需要腾讯云密钥，
不应为了建索引把密钥放进函数里。所以这一项**确实只能在控制台点**，
下文给的是可以照抄的清单。

## 二、当前系统的规模特征（事实）

### 数据库集合与查询模式

`setupdb` 只创建集合，**没有创建任何索引**（`createIndex` 在全仓出现 0 次）。实际查询如下：

| 集合 | 查询条件 | 排序 |
|---|---|---|
| `projects` | `ownerOpenId` | `createdAt desc` |
| `inspections` | `projectId` / `inspectorOpenId` / `deleted` | `createdAt desc` |
| `inspection_items` | `inspectionId + deleted` / `inspectionId` / `projectId` | `sortOrder asc` |
| `reports` | `projectId` / `inspectionId + deleted` | `createdAt desc` |
| `users` | `openId`（唯一） | `updatedAt desc` |
| `app_settings` | `openId` | — |
| `privacy_requests` | `openId` | `createdAt desc` |
| `memos` / `chat_analysis` | `projectId`（遗留读写，无写入方） | — |

### 云函数

`ai`、`auth`、`inspection`、`project`、`report`、`settings`、`speech`（共 7 个在用）。

**超时（2026-10-09 实测线上配置）**：`ai` / `report` / `speech` 60 秒，
`inspection` 20 秒，`project` / `auth` / `settings` 10 秒。
`ai` 内部给自己 45 秒预算 + 35 秒重试保留，落在 60 秒里有安全余量。

> **更正**：本文曾写「`setupdb` 刻意不部署」，但 2026-10-09 查询线上函数列表，
> **`setupdb` 实际在线上**（超时 60 秒）。它本身是安全的——未配置 `ADMIN_OPENIDS`
> 时整个函数失败关闭，白名单内的账号才可调用。但「文档说没部署、实际部署了」
> 这种不一致本身就是风险：以后判断线上有哪些入口时不能只信文档。
> 若确认不再需要，可在控制台删除该函数。
**8 个函数的 package.json 都没有声明 `timeout`**，全部使用平台默认值。

### 存储

`inspection-images/user/{openId}/`、`speech-input/user/{openId}/`、`logos/user/{openId}/`、`archive/…`。

**一张照片最多会存三份**（`inspection-media.js` 的上传字段）：

| 字段 | 目录 | 内容 |
|---|---|---|
| `sourceOriginalImagePath` | `inspection-originals` | 标注前的原图 |
| `imagePath` | `inspection-images` | 报告使用的主图 |
| `annotatedImagePath` | `inspection-annotated-images` | 带编号标注的导出图 |

加上语音文件，一次 20 张的巡查最多产生 60 个图片对象。

## 三、头号问题：没有索引

### 为什么这是最急的

云开发数据库**按读取次数计费**。没有索引时，一个 `where` 查询要扫描整个集合：

- 集合 1000 行 → 每次查询读 1000 次
- 集合 10000 行 → 每次查询读 10000 次

也就是说：**打开一次报告列表的成本，随你的数据量一起涨**。慢和贵是同一个原因。

### 两种做法

**做法 A：跑一次脚本（推荐，索引清单在仓库里）**

```bash
WX_APPSECRET=你的小程序密钥 node scripts/ensure-indexes.cjs --dry-run   # 先看计划
WX_APPSECRET=你的小程序密钥 node scripts/ensure-indexes.cjs             # 真建
```

- 密钥只从环境变量读，**脚本不写文件、不回显、不落盘**。
- 幂等：已存在的索引会被接口拒绝，脚本按「已存在」处理并继续，可重复跑。
- 清单就在 `scripts/ensure-indexes.cjs` 里，改索引改脚本，不再依赖谁记得住。
- `tests/index-plan.test.cjs` 会保证脚本与本文档的清单一致，防止两处漂移。

> 用的是云开发 HTTP 接口 [`updateIndex`](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloud/reference-http-api/database/updateIndex.html)。
> 之所以不做成云函数自动执行：那需要把 AppSecret 放进云函数环境变量——
> **拿一个更贵的凭据去换一个更便宜的问题**，不划算。

**做法 B：在控制台点**

### 在哪儿点

1. **微信开发者工具**顶部工具栏 → 点「**云开发**」（云朵图标），打开云开发控制台
2. 左侧导航 → 「**数据库**」
3. 左侧集合列表里**点选一个集合**（例如 `projects`）
4. 右侧区域切到「**索引管理**」标签页
5. 点「**添加索引**」，填三样：**索引名称**、**索引属性**（唯一 / 非唯一）、**索引字段**（每个字段选升序或降序）
6. 确定。六个集合照此重复

**建完怎么确认生效**：同一个「索引管理」页会显示每个索引的**占用空间**与**命中次数**。
跑一遍小程序（打开项目列表、报告列表等），回来刷新，命中次数不再是 0 就说明查询真的走了索引。

### 建议创建的索引

复合索引的字段顺序按「**等值在前、排序在后**」：

| 集合 | 索引字段 | 类型 | 服务的查询 |
|---|---|---|---|
| `projects` | `ownerOpenId`↑ + `createdAt`↓ | 复合 | 项目列表 |
| `inspections` | `projectId`↑ + `createdAt`↓ | 复合 | 项目下的记录列表 |
| `inspections` | `inspectorOpenId`↑ + `createdAt`↓ | 复合 | 「我的记录」 |
| `inspection_items` | `inspectionId`↑ + `deleted`↑ + `sortOrder`↑ | 复合 | 报告条目读取 |
| `reports` | `projectId`↑ + `createdAt`↓ | 复合 | 项目报告列表 |
| `reports` | `inspectionId`↑ + `deleted`↑ | 复合 | 由巡查查报告 |
| `users` | `openId` | 唯一 | 账号读取（**必须唯一**，否则可能一人两条） |
| `app_settings` | `openId` | 唯一 | 报告资料读取 |
| `privacy_requests` | `openId`↑ + `createdAt`↓ | 复合 | 我的申请列表 |

> `users.openId` 与 `app_settings.openId` 这两条**建议设成唯一索引**：代码按 openId 取「最新一条」，若不唯一，并发写入会产生重复账号记录。
>
> **唯一索引的坑（官方文档明确说明）**：记录里**不存在**某字段时，该字段对索引而言视为 `null`；
> 唯一索引不允许存在两条及以上该字段为空/缺失的记录。所以**如果创建唯一索引时报错，
> 说明集合里已经有重复或缺失 `openId` 的数据**——这本身就是要排查的问题，别绕过它。

**不用手建的**：云开发会给每个集合默认建 `_id` 与 `_openid` 索引。代码里
`db.collection(x).doc(id)` 命中 `_id` 索引；但 `where({ ownerOpenId })`、
`where({ openId })` 查的是**自定义字段**，不会命中 `_openid`，必须按上表自建。

**创建索引不会丢数据**，可随时删除重建。建议**上线放量前就建好**——事后补建时，已有查询已经开始全表扫描了。

## 四、照片：成本的主发动机

### 事实

- 上传 **原图**（`sizeType: ["original"]`），手机拍摄单张常见 **3–8 MB**
- 报告里每张问题照片还额外存一张**标注图**（在原图副本上画编号）
- 报告分享给接收者后，对方**每次打开都重新下载全部原图**（`getTempFileURL` 签发的是原文件）

### 估算（按每张原图 5 MB）

| 规模 | 照片总量 | 存储 |
|---|---|---|
| 10 个活跃项目 | 200 张 | ≈ 1 GB |
| 100 个活跃项目 | 2000 张 | ≈ 10 GB |
| 1000 个活跃项目 | 20000 张 | ≈ 100 GB |

**流量是另一笔**：一个 3 张照片的报告被查看 10 次 ≈ 10 × 15 MB = 150 MB 出网流量。

### ✅ 已实施：上传前压缩

`services/inspection-media.js` 现在在每次上传前调用 `compressForUpload()`：

- **只压长边超过 2000px 的**。2000px 约为手机屏宽的 2.5 倍，放大看裂缝、
  崩边、收口缺口仍然够用；而手机原图普遍 3000–4000px，命中率高、收益大。
- 尺寸已达标的一律不动，避免为省一点体积给本就不大的图引入重编码损失。
- 质量 85，按长边等比缩放。
- **任何一步失败都原样上传原图**：压缩是省钱手段，不能因为它挡住用户记录现场。

> 本地仍保留未压缩的原图路径（`p[localField] = local`），
> 之后重新标注用的是未压缩那份，不会因为省钱损失标注精度。

### ✅ 已实施：标注图改 JPEG

标注画布此前导出 **PNG**。画布内容是「照片 + 矢量标注」，PNG 对连续色调画面
几乎不压缩，2400px 一张常常**比原图还大**，是单张照片里最大的对象。
现已改为 **JPEG，质量 0.92**——编号与框线的可读性是产品核心，不用低质量换体积。

> ⚠️ **这一项建议真机复看一次**：放大后标注编号是否依然清晰。不满意就把
> `annotation-canvas/index.js` 里的 `fileType:"jpg",quality:0.92` 改回 `"png"`。

### 仍可优化

- **报告读者看缩略图，点开才加载原图**。目前读者下载的是主图与标注图全尺寸。
- **已删除记录的照片清理**。删除是 `deleted: true` 软删，**云存储文件不会随之删除**
  （全仓 `deleteFile` 调用为 0）。删掉的项目照片仍占着存储和钱。
  建议做成「删除满 N 天后由运营者手动清理」而不是自动删——软删是刻意的保护。

## 五、成本与容量：什么时候要掏钱

云开发各资源有免费额度，超出后按量计费。**具体额度与单价以控制台实时显示为准**（套餐会变，本文不写死数字）。

需要盯的四项：

| 资源 | 什么时候开始告急 | 怎么降 |
|---|---|---|
| **数据库读次数** | 建索引后大幅下降；不建索引会最先超 | 建索引、减少不必要的轮询 |
| **存储容量** | 照片堆积，只增不减 | 上传压缩 + 清理已删除记录的文件 |
| **CDN 流量** | 报告被转发得多 | 缩略图 + 原图按需加载 |
| **云函数调用次数** | AI/ASR 调用，按次计费 | 见第六节的配额 |

**建议动作**：在控制台打开**费用告警**，设一个你心理上能接受的月度阈值（例如 50 元 / 100 元），到阈值发短信。不要等到账单出来才发现。

## 六、AI 与 ASR：必须加限额

### 现状

- `ai` 调 **OpenAI 兼容接口**（线上实测 `provider: "openai-compatible"`、模型 `deepseek-flash`，由 `AI_BASE_URL`/`AI_API_KEY` 指定；混元只是未配置时的兜底），`speech` 调腾讯云 ASR。两者均**按量计费**
- 代码侧**没有任何调用频率限制或日额度上限**
- 历史上出现过 HTTP 402（额度耗尽），代码对 402 有兜底文案，但**不会阻止继续消耗**

### 风险

一个用户反复点「AI识图」，或一批用户同时用，费用会**无上限增长**，而且失败之前没有任何预警。

### ✅ 已实施：按账号的每日 AI 额度

`ai` 云函数在 `createInspectionTask` 入口处统计该账号当日（东八区）已创建的
任务数，超过上限直接返回：

> 今日 AI 识别次数已达上限（200 次）。可先用手动填写与标注完成记录，明天恢复。

- 上限由环境变量 **`AI_DAILY_LIMIT`** 控制，默认 **200**；设为 0 或负数即不限制。
- 按**东八区日历日**计算，与运营者直觉一致。
- **计数失败时放行**：额度是成本控制手段，不该因为一次查询异常挡住用户记录现场；
  真正的兜底是下面的用量告警。
- **手动路径不受影响**：拒绝文案明确指向「手动填写与标注」，主流程始终可用。

### 仍需你在控制台做

1. **给混元与 ASR 设用量告警**——这是第一道闸，比代码更早发现异常。
2. **监控 402**：一旦出现说明额度已尽，应立刻收到通知而不是等用户反馈。

### 关于 ASR

本次只给 **AI 识图**加了额度。语音转写走 `speech` 云函数、单独计费，
如需同样限制可在该函数的入口加一段同构的计数逻辑。

## 七、要盯什么（监控清单）

云开发控制台可看，建议**每周固定看一次**，出现异常再加密：

| 指标 | 在哪看 | 异常信号 |
|---|---|---|
| 云函数错误率 | 云函数 → 日志/监控 | 任一函数错误率 > 1% |
| 云函数超时 | 同上 | 出现超时（说明数据量或外部依赖变慢） |
| 数据库读次数 | 数据库 → 监控 | 与用户量增长不成比例地涨 → 索引没生效 |
| 存储用量 | 存储 → 用量 | 斜率突变 |
| 调用次数 TOP 函数 | 云函数 → 监控 | 异常集中的调用（可能是滥用） |
| 费用 | 费用中心 | 设阈值告警 |

**业务侧还应看**：每天新增项目数、新增报告数、AI 识图触发次数、语音转写次数。这四个数能解释绝大多数成本变化。

## 八、出事了怎么办（故障响应）

### 场景一：某个云函数报错率飙升

1. 控制台 → 云函数 → 该函数 → **日志**，按时间倒序看错误堆栈
2. 判断是**代码问题**还是**外部依赖**（腾讯云 ASR / 混元 返回错误通常是外部）
3. 若是刚部署引入的：**云函数支持版本回退**，在控制台把 `$LATEST` 指向上一版本，秒级回滚
4. 若是外部依赖：`ai` 与 `speech` 失败时**不应阻塞主流程**——手动填写与手动标注必须始终可用。这一点代码已按此设计，验证时请确认

### 场景二：数据库被写坏 / 误删

1. 控制台 → 云数据库 → **备份与回档**（如果已开启）
2. **现在就确认这个功能是否可用**——很多人在真正需要时才发现从未开过
3. 代码侧的保护：删除都是 `deleted: true` 软删，不会物理删除；报告有 `snapshot` 版本，重新生成不会覆盖历史

### 场景三：小程序本身出问题

1. **紧急回退**：公众平台 → 版本管理 → 「版本回退」，可退回上一个线上版本
2. 注意：**回退小程序不会回退云函数**。云函数要单独在控制台回退
3. 发布前务必按 [发布流程](发布流程.md) 冻结版本并留回执

### 场景四：AI/ASR 额度耗尽

- 用户会看到「额度不足，可直接按原文核对」
- **主流程不受影响**（手动路径完整）
- 立刻充值或临时关闭 AI 入口

## 十、合规运营（上线后是义务，不是选项）

1. **权利申请必须有人处置**。现在申请会写入 `privacy_requests`（`status: received`），但**仓库内没有处理界面**，也没有时限约束。上线后这是法定义务。
   - 最低成本做法：每周固定查看一次 `privacy_requests` 集合，处理后手工把 `status` 改为处理结果，并在页面上回填 `response` 字段（页面已支持显示）。
   - 需要更规范时，再做一个运营端界面。
2. **注销 ≠ 删除数据**。当前注销只做到「受理」。若用户要求删除，需要人工到各集合清理该 openId 的记录**以及云存储里的照片**。
3. **建议指定一个人负责**。哪怕是你自己、每周半小时——**没有人负责的合规入口，等于没有**。

## 十二、随规模增长的检查点

把下面这张表当成「到了这个量，先做这件事」：

| 里程碑 | 先做什么 |
|---|---|
