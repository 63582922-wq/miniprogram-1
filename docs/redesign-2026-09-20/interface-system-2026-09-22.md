# 毫厘智管 · 现场记录册界面系统

## 四个设计判断
- 角色：现场记录工具，不是营销落地页；照片和文字应占主要面积。
- 距离：手持手机，正文目标 16px，最小辅助字 13px；不靠缩小字体容纳信息。
- 气质：安静、可信、有现场感。暖纸色承载现场内容，中性墨黑负责信息，朱砂橙只用于拍摄、保存和关键标注；不再保留深墨绿这一套额外色相。
- 容量：375px 页面左右 20px；一级标题区约 88px，搜索 48px；项目行按内容自然增高。固定操作不能覆盖最后一条内容。

## 组件状态矩阵
| 组件 | 默认/选中 | 等待/禁用 | 错误与恢复 |
|---|---|---|---|
| 导航 | 三等分，当前图标与文字使用中性墨黑、下方朱橙短线；底栏保持暖纸色 | 切换成功再同步 | 失败留在原项 |
| 主按钮 | 朱砂橙、完整操作动词 | 文案+原生 loading，防连点 | 不跳页，保留输入，提供重试 |
| 项目行 | 名称→地址→记录数量与日期；透明底与细分隔，不做后台式卡片 | 加载独立呈现 | 无权限不得替换项目 |
| 输入 | 浅底细线，16px | 提交锁定 | 就近提示，不清空输入 |
| 照片 | 原图独立，说明连续 | 保存/上传进度 | 本地持久化失败明确阻止离开 |
| 标注工具 | 文字+图标、当前工具可辨 | 撤销/重做不可用弱化 | 不将未保存标记为成功 |
| 资料 | 巡查人/公司/LOGO 分组 | 身份和资料加载分别呈现 | 禁止用“微信用户”掩盖失败 |

## 现场记录册边界
项目只回答“这份现场记录属于哪里”。页面不得引入施工阶段、负责人、任务、整改进度、流程编号等施工管理语义；不编造项目照片、人员或状态数据。照片由用户现场采集后成为页面主内容，未有照片时用明确空态承接。

## 全局页面语法（正式实现依据）

- 根页只出现一次紧凑产品识别：几何标记、`毫厘智管` 与能力说明；二级页不重复产品头。
- 每一页都是一张连续的暖纸面。项目、照片、问题和报告段落由细分隔线组织；不得用阴影、彩色块或嵌套圆角去伪造层级。
- 一个屏幕只存在一个实心主动作：项目页是“新建项目”或“拍摄现场照片”，项目详情是“继续/拍摄现场照片”，采集页是“进入人工核对”，核对页是“确认内容并生成报告”，报告页是“转发这份报告”。AI、PDF、编辑、筛选均是次级文字动作。
- 项目页只说明归属、记录数量、报告数量和最近内容；禁止出现施工阶段、责任人、整改或“工作台”语义。
- 采集页先让用户看到当前项目和照片。照片打开即标注；文本、录音和 AI 均不阻挡纯手动完成。
- 标注页优先给照片高度。第一行仅保留选择、矩形、圆形、箭头、编号；移动、撤销、适应和删除为第二行；对象被选中才显示微调。
- 核对页按“问题 一”照片分组，组内保留 `1. / 2.`；照片不被多重容器切碎，无问题照片也保留并明确“不代表验收合格”。
- 报告是阅读文档，不是应用仪表盘：报告抬头使用公司 LOGO、公司名、巡查人和电话，产品标记不冒充公司 LOGO。分享路径始终带当前 `reportId` 与只读令牌。
- “我的”是出具资料的准备页：公司名称、LOGO、巡查人、电话四项直接可见；空值显示缺失状态和编辑入口，发布后的报告使用冻结快照。

## 原型与品牌资产边界
`convergence-master.html` 是可点击规格演示，不冒充生产验收。演示内容均标为示例；公司 LOGO 由用户自己的资料上传，不用默认头像或虚构 LOGO 代替。已有用户截图是修复前依据，旧 HTML 保留历史，不再作为新导航依据。

## 发布资料
公司名称/LOGO/地址/电话、巡查人/电话和报告出具人随发布快照冻结。微信里的二次转发者不可从分享链接可靠认证；展示“报告出具人”，不能伪称“当前转发人”。
