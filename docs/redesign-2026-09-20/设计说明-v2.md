# 毫厘智管 · 现场记录册 / 母版02

本版根据用户对第一版“缺乏审美、偏离原链路”的反馈重新设计。仅为可评审母版，未更改业务代码。取代第一版关于重组导航、单独交付页和新编号的建议。

## 设计使用的技能

- visual-layout-design：先定义内容层级、画布尺寸、对齐和阅读顺序，再处理字体与色彩；按实际导出的截图审阅。
- huashu-design：以HTML输出可操作母版，复用现有项目内容，检查关键交互和窄屏表现。本轮用户已明确三屏与收敛方向，直接制作具体审阅结果。
- imagegen：生成一张示例窗边照片作为三屏共同素材，明确标记非真实巡查证据；不生成新的业务结论。

## 固定的产品边界

沿用：项目 → 拍照/标注/按住说话 → AI整理 → 核对 → 报告。

保留现有导航；保留“问题 一”作为照片分组，以及组内“1. / 2.”的问题编号。一个照片组允许多个问题。报告内保留微信转发和PDF，不新增交付页面。不新增工作台、待办、整改管理。

收敛：项目概览和选择合成一行；选填标题/现场补充收起；核对页默认阅读，点击编辑才展开描述、建议、责任方；核对后直接报告，省掉重复巡查详情。问题编号的稳定性由数据实现保证，本次不重定一套编号。

## 视觉命题

一份清楚、克制的专业现场记录册。现场照片先被看见，文字解释照片，主操作位于稳定位置。

暖白#FCFBF8为画布，墨色#282923用于文字与主操作，朱砂#A44938用于标注。灰绿仅用于辅助信息。风险必须有明确文字，不靠颜色推断。

采集、核对用系统无衬线，标题约29px，内容13–16px。报告标题用33px宋体，保持其他信息无衬线。宋体只用于少量标题和分组标题，不用于连续输入或操作说明。

统一24px边距。照片、标题、问题正文遵循同一对齐线。去掉重复卡片与框线，以段落间距和细分隔组织。主按钮48px；微操作在正式小程序中扩大透明触控区，不通过缩小字体压缩全部内容。

三屏是微信内容画布示意，不是iPhone外壳；正式开发必须依据微信胶囊、安全区和键盘高度校准。

## 交互母版范围

未接入：真实录音、AI、上传、业务保存、分享、PDF。示例编辑刷新后不保留，不能当作已经实现了生产草稿。替换照片后隐藏示例标注，避免把旧标注误套在新图片上。
