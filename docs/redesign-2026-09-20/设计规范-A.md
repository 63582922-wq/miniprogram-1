# 毫厘智管 · 现场记录册 / 唯一实施规范

> 本文件保留原路径以兼容历史链接。旧“石墨＋酸橙、全无衬线”的 A 方案已经作废；以下暖纸、墨黑、朱橙和双字体职责是唯一现行规范。

## 设计意图

产品只服务一条任务：进入项目，拍摄现场，准确标注，人工核对，交付一份清楚的报告。项目只定义记录归属，不把产品扩展成施工管理后台。

界面像一本安静、可信的现场记录册：照片先被看见，文字解释照片，操作只在需要时出现。专业感来自准确对应、清楚阅读和可恢复，不来自大量卡片、深色面板或装饰性仪表。

## 颜色

| 角色 | 色值 | 使用范围 |
|---|---|---|
| 暖纸 | `#E9E4DD` | 页面、导航、底栏、固定操作区 |
| 输入面 | `#F2EEE8` | 输入框及需要区分的轻背景 |
| 中性墨 | `#191816` | 正文、图标、主要标题、按钮文字 |
| 辅助灰 | `#706D67` | 元数据、说明、未选中导航 |
| 分隔线 | `#C9C1B7` | 连续内容之间的细分隔 |
| 照片留白 | `#DDD6CC` | `aspectFit` 图片周围的中性暖灰 |
| 朱橙 | `#DE6E3F` | 主操作、标注选中、当前导航短线 |
| 深朱橙 | `#C75C35` | 主操作按下态 |
| 小号强调 | `#B74F2D` | 小字号选中与警示文字 |

正式界面、Logo、应用图标、标注画布和 PDF 不使用墨绿色相。朱橙不用于大面积装饰或普通信息强调。

## 字体与排版

只允许两种字体职责：

- 展示宋体：`Songti SC` 优先。用于品牌名、含中文的项目／报告对象标题、照片标题、记录进度和报告封面。
- 系统黑体：`PingFang SC` 优先。用于导航、按钮、列表、表单、说明、数字，以及纯英文／编号对象名。

不要仅因文字字号大就使用宋体。`QA-0922-B` 这类纯英文编号必须使用系统黑体，避免类似 Times 的错误观感。

正文约 16px，辅助信息 13–14px，主要对象标题约 24–30px；字重只使用 400、500、600。最小辅助字号为 13px。数字使用等宽数字属性，不下载第三套字体。

## 布局与组件

- 页面水平间距约 18px，使用 8px 节奏。
- 页面为连续纸面；照片、说明和问题通过留白与细线组织，不层层套卡。
- 项目等独立对象可形成列表单元，但不使用浮层阴影和大圆角容器。
- 主要控件圆角约 4px，主要按钮高 52px，次操作不低于 44px；所有触控区域至少 44px。
- 一级导航仅保留项目、报告、我的。三个图标采用同线宽轮廓；当前项用墨黑图标／文字和朱橙短线，不使用实心图标或背景块。
- 一级页显示产品识别和紧凑栏目标题；二级页只显示返回、页面标题和必要的内容操作，避开微信胶囊。
- 每屏只有一个明确主操作。次操作使用文字、细边或内容行，不与主操作争夺视觉重量。

## 页面职责

- 项目：选择记录归属、创建项目、从项目详情开始或恢复记录。
- 现场记录：照片是主内容；语音、文字和现场补充围绕当前照片出现。
- 精准标注：照片占据主要空间；工具为选择、移动、框选、圈选、箭头、编号、撤销、重做、放大、全图和删除。
- 人工核对：按照片分组核对，可修改、删除或新增问题；AI 只提供建议。
- 报告：只读呈现冻结快照；转发当前报告为主操作，PDF 为独立次操作。
- 我的：展示微信身份、巡查人、联系电话、公司名称、公司电话、Logo、使用说明和隐私入口。

## 照片与标注

照片预览默认保全画面，不为了版式裁掉现场信息。标注支持选择、平移、框、圈、箭头、编号点、选中移动、端点调整、撤销、重做、删除和 1 工作图像素微调。

双指缩放围绕手势中心，并取消未完成的单指绘制。可见线条和触控命中范围分离；拖动时显示避开手指的局部放大镜。原图、可编辑标注和渲染图分开保存，共用方向校正后的原图坐标。

## 状态与文案

- 按下反馈 120–220ms；标注手势实时响应，不添加拖慢定位的装饰动效。
- 加载、空数据、无搜索结果、错误、禁用、处理中、成功必须语义分离。
- 上传、转写、AI、PDF 失败都要说明原因并提供继续路径；保存失败不能显示成功。
- 零问题照片保留为“现场照片”，文案必须说明“未记录问题，不代表工程验收合格”。
- 有问题的照片保持“问题 一／1.／2.”结构，不重编号历史内容。

## 验收

HTML 母版只证明设计方向。正式验收必须来自原生小程序运行态、隔离数据、保存后重开、单份报告读取和真实交付状态。

当前视觉对照、截图与自动检查见项目根目录 `design-qa.md`。真机字体、触控、键盘、权限与安全区必须另行记录，不能用模拟器替代。
