# 毫厘智管：复审与单链路改造计划

2026-09-20 · 基于当前本地代码的二次审查 · 方案待评审，未修改业务代码

> 后续修订：用户要求基于原主链路收敛。以下导航重组、另设交付页及新编号建议已撤回，最新设计边界见《设计说明-v2.md》。代码问题分析仍保留，实施需按新版边界执行。

## 1. 对需求的理解

用户要一个聚焦装修现场、能实际商用、操作省心的产品，以及全新的视觉体系。首要用户暂定为亲自到现场检查并向业主或施工方交付记录的人，可能来自装修公司、建材商家或独立巡检团队。这个人首先需要记录不丢、图片与问题不串、描述准确、交付方便。组织管理和整改协同有价值，但不能先用它们扩大第一版。

建议本期承诺：从现场照片和口述，整理出经人核对、证据对应清楚、可在微信阅读的巡查报告。AI提供整理建议；用户决定最终内容。对于照片看不出的隐蔽问题、尺寸和材料性能，允许标记“需现场核实”，不可凭图片补造结论。

建议成功标准是任务完成率、丢失与重复情况、核对修改量和可读性。上一轮提出“3分钟完成”缺少测试依据，撤回为承诺；后续按照片数分组实测耗时再设目标。

## 2. 本轮证据边界与更正

- 已读取页面路由、自定义导航、首次进入、采集/标注/核对/报告页面、云调用包装、项目/巡查/AI/报告云函数和PDF服务。
- 自定义导航确有拍照入口，上一轮仅根据app.json判断入口隐藏不准确。实际问题是模板只绘制图标，未输出已定义的文字标签。证据：`miniprogram/custom-tab-bar/index.js`、`index.wxml`。
- 当前云环境配置已是新环境，部署文档也记录了环境迁移。旧的Env Not Exists记录不是当前故障证据；本轮没有调用线上环境，因此在线健康状态未验证。
- 两次尝试连接本地应用界面均超时，没有拿到当前小程序截图。本报告属于代码与流程设计审计；视觉可读性和误触概率属于待真机验证的设计判断。
- 没有执行云端写入、收费AI/语音/PDF请求或真实分享。母版中所有项目、数字、问题文案都是标注的示例。

## 3. 当前架构

微信小程序页面 → services/cloud（云调用与默认重试） → 微信云函数 → 云数据库/云存储。

AI云函数另接模型服务；speech另接语音服务；report另接独立Express/Puppeteer PDF服务。总体技术栈足以支持当前单链路，暂无证据需要迁移框架或重写后端。

实际流程：项目页首次进入可能自动跳企业设置 → 建项目 → 相机/相册 → 巡查采集 → 可选标注与语音 → 上传 → AI整理 → 核对 → 提交巡查 → 巡查详情 → 打开报告 → 保存报告/分享 → 可选PDF。

已有可保留资产：按项目所有者鉴权、AI任务归属检查、随机分享token、上传路径隔离、统一草稿形状、误报删除与编辑、PDF失败不阻断报告阅读。不能把这些当成不存在后重新造一套。

## 4. 问题清单：事实、影响、优先级

### A. 提交重试缺乏幂等保护 — P0

事实：`services/cloud.js:47`起默认超时最多调用三次；`services/inspection.js`确认操作未关闭默认重试；`cloudfunctions/inspection/index.js:107`起每次confirm都add巡查，再Promise.all写问题，再更新项目，没有请求去重或事务边界。`cloudfunctions/project/index.js:57`创建项目也直接add。

影响推断：服务端成功但回包超时时会重复创建；部分问题写入失败时可能留下不完整巡查。前端submitting只能挡连点，不能解决网络重试。尚未在生产复现。

计划：创建和确认均带稳定clientRequestId；服务端验证、唯一约束/事务或可恢复提交协议；返回同一业务记录。不能仅关闭重试后把不确定结果交给用户。针对“已写成功但回包超时”“部分子项失败”做故障注入验证。

### B. 原照片与问题的稳定身份没有贯穿保存 — P0

事实：确认页通过sourceIndex与图片路径分组；confirm写入问题时未保存sourceIndex、subIssueIndex和独立sourcePhotoId；报告页再以主图片路径为key分组，缺索引则退回条目位置。证据：`pages/inspection/result/index.js:13`、`cloudfunctions/inspection/index.js:150`、`pages/report/detail/index.js:80`。

影响推断：同源图片替换、标注版本差异、合并/重排后，分组与编号可能漂移。路径相同不等于问题身份相同，不能只靠字符串维护证据关系。

计划：Photo.id → Issue.sourcePhotoId → Issue.id；原图、标注图、语音分别引用稳定资源ID；同一照片允许多个问题，问题编号在发布版本内固定。小程序与PDF读取同一份报告快照。

### C. 草稿与核对结果的持久化不完整 — P0

事实：采集页有本地草稿，不是完全没有草稿；但结果页handleItemChange/handleDeleteIssue只更新setData，未回写当前核对快照。completeAnalyzeSuccess写新结果草稿后clearDraft，最新草稿入口不再指向核对中的结果。证据：`pages/inspection/create/index.js:1035`、`pages/inspection/result/index.js:145`。

影响推断：退出/重启后难以找回结果页，已经编辑的内容可能丢失。缓存临时文件路径也不等同于图片已持久保存。

计划：统一一份有version、userId、projectId、stage、photoIds、issueIds、taskId的草稿记录；每次编辑/删除落盘；本地媒体转持久文件，上传成功逐项登记，重试只处理失败项。首页明确“继续未完成巡查”。

### D. AI查询接口承担任务执行，恢复状态耦合页面 — P0/P1

事实：AI getInspectionTaskStatus在queued/running时调用processAnalysisTask；采集页onHide停止轮询；取消等待清空当前taskId。task写running前未见原子抢占锁。证据：`cloudfunctions/ai/index.js:1177,1430`、`pages/inspection/create/index.js:309,1021`。

影响推断：当前调用可能继续执行，但后续批次依赖再次查询推进，不能承诺离开后自动完成；并发查询可能重复处理同一批次。取消等待不等于取消云端计算和费用。

计划：立即持久化任务ID和批次结果；区分停止等待/取消任务/重试。先补租约与幂等；再根据云服务支持选择独立执行器、触发器或队列，查询接口只读。短期若仍查询驱动，要明确显示“返回后继续整理”。

### E. AI失败与零问题场景没有完整出口 — P1

事实：采集页主提交动作是handleAnalyze；结果页空数组弹“没有可提交的问题”并返回；未见面向用户的完整手工记录发布路径。

影响：模型不可用时核心业务被阻断；“本次未记录问题”也无法正常交付。不得把AI没识别出问题自动等同于验收合格。

计划：支持手工补问题与发布现场记录；零问题报告写“本次未记录问题，不代表全面质量验收结论”，经用户确认再发布。

### F. 失败态和空态仍混用 — P1

事实：项目列表只有projectList，失败只toast，WXML空数组就显示“还没有项目”；搜索无匹配也进入同一空态。safeGetList捕获错误后返回空数组。环境分类还把任意cloud.callfunction fail归为环境错误。

计划：idle/loading/ready/empty/no-results/error明确分离；错误有重试、已有缓存可继续看；技术细节进入诊断，不要求现场人员修改环境ID。

### G. 查询规模与统计不可靠 — P1

事实：项目、巡查和关联统计多处直接get后在内存计算，无完整分页。项目列表忽略传入pageSize；报告列表自身分页，但前置项目ID查询未分页。证据：`cloudfunctions/project/index.js:117`、`cloudfunctions/inspection/index.js:53`、`cloudfunctions/report/index.js:588`。

影响推断：数据超过单次查询返回范围后会遗漏记录或统计偏小。本轮不猜测SDK具体上限。

计划：服务端筛选和游标分页；count/聚合或维护计数；权限先判定指定项目，避免依赖一页项目列表推导全部权限。验证跨页项目及历史记录。

### H. 首次进入与页面层级增加操作负担 — P1

事实：project/list.tryShowOnboarding引导未完成就跳settings或project/form；提交巡查后先去inspection/detail，再goReport；项目表单初始同时展示甲方电话、状态和说明。

计划：首次先创建最少必要的项目资料；联系人、企业抬头可稍后补。最终核对后直接到报告；巡查详情保留为历史记录入口。需要同意的隐私授权仍在首次使用相关能力前完成。

### I. 商业协作能力尚未形成 — 后置

事实：项目teamId为空，项目访问按ownerOpenId；分享报告为只读token访问。现有“责任方”是分类字段，不等于绑定了真实协作人或送达通知。

结论：当前更接近个人巡查与报告交付工具。多角色权限、邀请、通知、整改证据、复查状态都需要独立设计。母版不展示不存在的整改率、送达率和责任人任务。

### J. 视觉系统与交互语义不一致 — P1

事实：tokens.wxss定义蓝黑/橙色与无衬线；app.wxss未导入它，使用米色/衬线；页面硬编码大量颜色和18–22rpx小字。图标导航没有文字。表单字段、删除、收起、数量标签外观相近。结果页“全部通过”可能被理解成工程验收通过。

判断：现场扫读需要更明确的字重、对比、点击范围和动作文字。冷白/墨色/单强调色是本次建议，不是经用户测试证明的唯一正确风格。

计划：唯一token来源；主操作使用实心按钮，次操作描边或文字，信息标签不可伪装按钮。正文目标16px、辅助文字13–14px、关键目标至少44px，按小程序rpx映射并在真机验证。提交文案使用“确认内容并生成报告”。

### K. PDF与分享需要生命周期治理 — P1/P2

事实：PDF服务taskStore为内存Map，进程重启丢任务；报告分享token创建后复用，未见撤销/过期入口；新建报告没有按inspectionId防重复机制。报告列表按generatedAt排序，未出PDF的报告该值可能为0。

计划：区分报告发布状态与PDF状态；按publishedAt排序；报告创建幂等；PDF任务持久化、失败可重试；分享可撤销/重新生成。PDF失败继续提供在线报告。配额与限流按真实调用成本设置，暂不承诺价格或无限用量。

## 5. 目标产品结构

首页“项目” → 项目详情（历史巡查/报告、继续草稿） → 现场记录 → 核对内容 → 在线报告。

“我的”保留企业资料与设置。主导航拟定“项目 / 开始巡查 / 我的”，其中开始巡查是动作，不是伪装成Tab的独立数据页。报告先在项目内按时间归档；如真实跨项目找报告需求显著，再增加全局入口。

从项目进入自动带入项目；全局开始时最近项目醒目显示且可更换。采集会话期间不放全局导航，避免误离开；退出自动保存并明确返回路径。

照片不是问题本身：同一照片可有多个问题；没有问题的现场记录也可保留。UI沿用用户的“问题一/子项”习惯，但在设计中将上层明确称“照片01”，问题使用01-1等稳定编号；编号策略确认后再统一迁移，不在实施中擅自更换。

## 6. 目标工程结构

保留原生小程序与微信云开发。拆出draft-store、media-upload、analysis-task、inspection-submit、report-snapshot等有明确职责的模块，页面只编排展示与用户动作。不为了重构把全部旧页面一次替换。

建议模型：Project → Inspection → Photo[] / Issue[] → PublishedReportSnapshot。Issue关联Photo与Annotation，保留AI原始建议和人工最终值。报告快照含schemaVersion、发布版本、稳定编号和资源引用；在线报告与PDF共用快照。兼容旧数据读取，不批量覆盖历史报告。

任务状态：draft → uploading → analyzing → review → submitting → published；失败保留所在阶段和可恢复动作。AI、上传、PDF各自有任务状态，不用一个loading布尔值代表所有事。

## 7. 执行计划与每阶段复核

| 阶段 | 要交付什么 | 完成判定 | 下一步 |
|---|---|---|---|
| 0 当前：方案与母版 | 复审、六屏母版、状态样式、范围边界 | 母版可打开，方案能指出保留/修改内容 | 确定视觉与导航 |

## 8. 有限而必要的验收场景

1. 新用户：隐私授权 → 建项目 → 一张照片 → 手工补充 → 报告；企业资料不阻断。
2. 回访：继续原草稿；核对页编辑后杀进程再恢复。
3. 同图两问题：删除一条、改另一条；在线与PDF原图/标注/描述/编号对应。
4. 上传失败、模型失败、提交响应超时：不丢输入、不重复创建、有可恢复动作。
5. 无问题：可发布事实记录，无“AI判定合格”的误导。
6. 多页项目与报告：筛选、统计和权限一致。
7. 分享：作者与接收者分别查看，接收者不能编辑或访问其他报告；撤销后旧链接失效。
8. PDF：进程重启后可恢复或明确失败；在线阅读始终不受影响。

记录通过/失败/阻塞/未观察。无新修改或新失败时不重复扩大验证。速度目标在真实网络和照片批量下采集首屏、上传、AI和总耗时分布后确定。

## 9. UI母版说明

`visual-master.html`为独立审阅文件，可直接打开，包含六屏总览、可点击主链路、三种视觉取向、异常状态和规范。默认“清晰蓝”推荐方向；“现场绿”强调低干扰；“黑白工具”强调高对比与紧凑。

母版使用现有产品中文名称作为文字标识，不另造Logo。项目内没有可用真实工地照片，本次保留明确的照片证据位并提供本地图片导入；图片只在当前浏览器内预览，不上传。演示数据不冒充真实项目。照片观感需导入真实现场图后再评审。

本阶段不接云服务，不模拟真实AI准确率，不把按钮演示当作已实现功能；正式小程序代码未更改。
