1. 开发者工具服务端口获准开启后，只做本机编译/自动化。确认登录身份对当前 AppID 有开发和体验版权限。

3. 记录现有客户端版本、云函数版本/配置、PDF 服务镜像或部署包、环境变量名称及集合规则。密钥只在服务端环境配置，不写报告、Git、截图或日志。
4. 用平台已有备份/导出机制保留受影响集合及索引/规则记录。不得清库、批量改历史报告、覆盖旧图或调用删除接口作“验证”。
5. 必须核实 AI/语音服务的供应方、模型、账户额度、单次计费和失败重试规则；PDF 服务地址/鉴权/进程管理方式。未核实前只走纯手动链路。

## 二、依赖和数据契约

### 客户端

保留原生微信小程序；当前项目基础库配置 3.7.3。新增会话、稳定 ID、图形几何及媒体服务均在 `miniprogram` 内，不需要迁移框架。保留本地图标及 `miniprogram/images/icons/lucide-LICENSE`。

原生 Canvas、文件保存、EXIF 解码行为须在当前基础库和设备确认，不以离线编译代替。草稿版本 2；原有草稿兼容读取。成功报告后清活动草稿，不主动批量删本机媒体。

### 云函数

部署有修改的 `project`、`inspection`、`ai`、`report`，每个目录都须包含其 `reliable.js`，并按现有方式安装各自 `package.json` 依赖。保留原 action 兼容入口；`auth/settings/speech` 等依赖功能仍需确认在线可用，不能因为此次未修改就视作可用。

沿用集合：`users/projects/inspections/inspection_items/reports/memos/chat_analysis/app_settings/subscriptions/ai_tasks`。先只读检查存在性；缺集合只建缺项，不覆盖、不重置。不要把 `setupdb` 暴露成普通用户可任意调用的管理入口。

重点核实：固定 `_id` 的重复添加行为；条件更新锁/提交状态；`ownerOpenId/deleted/updatedAt`、`projectId/deleted/inspectionDate`、`inspectionId/deleted/sortOrder`、任务归属等实际查询的索引；函数最大执行时间。AI 推进预算 45 秒、单请求 30 秒、租约 180 秒是代码配置，不是实际耗时承诺；运行上限须覆盖推进与数据库保存，否则要先调配置或缩短批次。

新字段：草稿 `schemaVersion/sessionId/inputVersion/taskId/review/submission`；证据稳定 ID 与 `sourcePhotoId`；巡查准备/完成状态；报告 `snapshotVersion/snapshot/publicationStatus/publishedAt/shareState/pdfTaskStatus/pdfAttempt/pdfTaskId`。采用新增字段与兼容读取，没有离线批量迁移任务。

云函数归属检查不能替代安全规则。确认客户端不能绕过函数直接读写他人的项目、任务、录音、报告或媒体。路径含用户 ID 只是合同约束，不是实际云端安全验证结果。

### PDF 服务

沿用 `report-pdf-service`，服务端设置 `PDF_API_KEY`，云函数 `report` 配置相同鉴权及 `PDF_SERVICE_URLS`。缺 key 时服务拒绝启动；客户端不持有 key。仅从已验证云存储域名读取图片，不为通过测试放开任意 URL 或 HTTP。

服务接受云端预先生成的 `jobId`，格式 `pdf-` 后 40 位十六进制字符；同进程重复请求同任务不会重复排队。进程重启仍可能丢失队列；云端会转为明确失败并支持原快照重试。此方案不声称持久队列自动续算。

安装现有依赖、检查 Chromium 和中文字体、运行健康检查和鉴权拒绝检查，然后才开放受控报告任务。`PDF_ALLOWED_IMAGE_HOSTS` 只补实际需要的可信域名；`PDF_ALLOW_HTTP` 保持关闭。不要将本机 `127.0.0.1` 写成手机可访问的服务地址。

## 三、发布顺序与中止点

1. 保存基线和备份，确认受控目标环境。
2. 先发布兼容 PDF 服务：保留旧同步端点，增加/确认可恢复 jobId 协议。只健康检查不生成报告；失败立即停止。
3. 部署兼容云函数；只读核实鉴权、可用集合、版本。新客户端尚不切入；发现旧版入口不可用即停止。
4. 本机加载新客户端，运行隔离纯手动项目：一张照片、一个问题、确认、重开在线报告。记录项目/巡查/报告 ID。重复确认同请求应还是同一份；不得使用真实客户记录做故障注入。
5. 已明确计费后，依次进行最小一组 AI、短语音和 PDF 测试。每项记录输入、请求 ID、结果、实际调用数量；失败先定位，不自动扩大样本/换收费供应方。
6. 作者与接收者分别读取、尝试越权、撤销旧链接、生成新链接；确认报告照片/编号/文字一致。下载的 PDF 不能被撤销。
7. iOS/Android 完成验收清单，重点检查标注端点/双指/放大镜、照片方向、语音取消、键盘和底部按钮。每阶段退出重进；20 张大图单独记录内存/时间/存储结果，不以小样本推断。
8. 修复只补测受影响项，再统一回归。全部门槛通过后才上传体验版，记录版本号、上传者、环境、二维码和体验成员。**不点击提交审核/公众发布。**

停止条件：任何数据丢失、重复记录、照片与问题错配、越权、旧数据变化、不可恢复提交、交付打不开，均阻止体验版验收通过。缺账号/设备/权限标记阻塞，不写“通过”。

## 四、回退策略

- 客户端出现问题：恢复已记录的上一可用客户端版本/体验包。保留新增后端字段、冻结报告和已上传媒体，不批量逆迁移。旧客户端不一定理解新版未完成草稿；不要主动清理草稿或用旧客户端覆盖它，必要时先回新版导出/完成记录。
- 云函数出现问题：优先回退有问题的兼容入口实现或修复小范围故障；不要直接换成完全不认识快照的旧后端，避免重新读取变化中的企业资料。需按实际记录的旧版本评估回退，不提供“任何版本无损回退”的保证。
- PDF 服务出现问题：在线报告仍可读。停止新 PDF 任务，恢复上一服务包；新版报告仍以固定快照保存。旧服务不支持 jobId 时先关闭新版发起操作，避免无法查询的任务继续累积。
- 已发出的 PDF、截图无法撤销。在线链接只按明确请求撤销，不因回退自动轮换全部链接。
- 任何恢复操作先精确列出受影响记录并备份，优先单条修复；禁止清空集合或回滚客户的后续合法编辑。

## 五、本地检查入口与证据来源

在项目根目录运行：`node tests/local-compile.cjs`、`node --test tests/*.test.cjs`。后者完全隔离，不需云密钥。本地 PDF 版式检查为 `node tests/pdf-layout.cjs`，依赖可用的 Playwright/Chrome；它不代替生产 Puppeteer 的服务验收。

本次腾讯 SDK 超时单位已根据 [官方 Node SDK HttpProfile 定义](https://github.com/TencentCloud/tencentcloud-sdk-nodejs/blob/master/src/common/interface.ts) 核实为秒，设置为 30 秒。部署时仍须核对实际安装版本和函数时限。

最终交付证据应包含：正式客户端截图、两平台设备/基础库版本、真实调用台账、隔离记录 ID、分享双方结果、实际 PDF、部署/回退版本、体验版二维码。本次已补充本机 PDF 服务的健康、鉴权、固定 jobId、完成与下载证据；这只证明本机服务合同可用，不证明远程服务、云存储写入、微信打开或生产配置可用。
