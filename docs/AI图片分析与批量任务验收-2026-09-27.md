# AI 图片分析与批量任务验收（2026-09-27）

## 目标

AI 只负责把现场照片、标注和说明整理成**待人工确认的建议**。准确不等于“输出问题越多越好”，而是：照片来源不串、可见证据能对应、没有证据时敢于返回空结果、现场说明中的疑问不被改写成既定缺陷。

当前还不能给出“准确率百分比”：四张测试照片没有经过具备现场责任的专业人员逐项标注，且真实模型调用被服务商 `402` 额度状态阻断。任何百分比都会是假精确。本文件先固定可复测样本、风险门槛和已验证事实；额度恢复后按同一标准补录模型结果。

## 本轮针对性修正

- 图片与语音并行使用：有语音不再跳过图片分析。
- 每张照片独立请求，稳定照片 ID 贯穿任务、核对和报告，避免多图串位。
- “请查看／是否存在／可能／疑似／待确认”只作为检查线索，不再强制生成问题。
- 纯图片问题必须返回具体 `visualEvidence`；没有可见证据且没有现场人员明确断言的条目会被丢弃。
- 只有现场人员以肯定语气明确记录的问题，才允许在图片证据不足时保留；此时强制标记为低置信度、待人工核对、证据来源为现场说明。
- 施工过程状态不自动判为质量缺陷；不推断真实尺寸、垂直度、强度、隐蔽层做法、责任方或规范结论。
- 零问题照片保留，界面明确提示“未记录问题不代表验收合格”。
- 修改或新增照片后，只重分析变化照片；未变化照片上已经人工确认的内容保留。

## 多照片最优路径

采用“异步任务 + 单图请求 + 有限并发”，不采用把 20 张图塞入一次同步请求：

运行态安全诊断已确认：`provider=openai-compatible`、`model=deepseek-flash`、`visionEnabled=true`、`imageDetail=high`、`batchSize=1`、`parallelLimit=3`、`maxPhotos=20`。单图请求也避开了模型在单请求图片数量增加时的降采样和多图来源混淆风险。

1. 客户端先把原图／标注图持久化并创建任务，立即获得任务 ID。
2. 服务端每张照片一个模型请求，默认最多并行 3 张。这样减少多图错配，也避免单次请求超过云函数时限。
3. 任一照片完成后立即写入检查点；客户端每 1.5 秒读取一次状态，可见 `0/20 → 1/20 → …`。
4. 用户可以返回记录页，任务和已完成结果保留；再次进入继续查询和推进，不重新分析已完成照片。
5. 某张失败时只重试未完成项；也可以直接进入人工核对，不让 AI 成为主链路阻塞点。

并发数不能盲目提高。当前额度状态未知且真实调用返回 402；恢复服务后应以 4、10、20 张三档记录首张结果时间、总耗时、429 比例和单图误配率，再决定是否从 3 调到 4。

## 通过门槛

- 照片来源错配：0。
- 没有可见证据且没有明确现场断言的缺陷：0。
- 检查疑问被改写成既定问题：0。
- 明确现场断言遗漏：0；若图片不能支持，必须低置信度并待人工核对。
- 4、10、20 张均逐张显示进度；失败重试不得重复已完成请求。
- 最终报告只包含人工确认后的快照；AI 原始建议不直接对外。
