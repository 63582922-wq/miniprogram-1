# 内测上线清单

> 冻结点：`v1.0.12`（2026-10-06）。照着从上往下做即可。
> 目标：把 `v1.0.12` 作为**体验版**发给内测人员。**不需要先走正式上线审核。**

---

## 为什么用体验版而不是先上线

| | 体验版 | 正式版 |
|---|---|---|
| 需要审核 | 不需要 | 每次改动都要 |
| 人数 | 体验成员（上限 100） | 不限 |
| 迭代 | 重新上传即生效 | 重新走审核 |

内测期间一定会改东西。走正式版意味着每改一次等一轮审核，迭代会被拖死。
**正式上线放到内测收尾之后再做。**

## 步骤 4 · 新建 `privacy_requests` 集合 —— ✅ 已于 2026-10-06 完成

**当时的实测结论：该集合不存在。** 在开发者工具模拟器里点「提交申请」，
云函数返回：

```
-502005 database collection not exists. [ResourceNotFound]
Db or Table not exist: privacy_requests.
```

所以这不是「去确认一下」，而是**必须新建**：

云开发控制台 → 云数据库 → 新建集合 `privacy_requests`。
权限设为「仅创建者可读写」或「所有用户不可读写」，访问只走云函数。

> 云开发不会在写入时自动建集合。不建的话，内测用户一点「提交申请」就失败
> ——这是合规功能，第一次用就失败很难看。
> 客户端侧已改为显示可读的提示（不再甩英文错误码），但**失败依然是失败**。

### 已完成与验证（2026-10-06）

用户在云开发控制台创建了 `privacy_requests`，权限设为「所有用户不可读写」
（客户端从不直连该集合，读写全走云函数；云函数用管理员权限，不受此设置影响）。

创建后按端到端验证：

| 检查 | 结果 |
|---|---|
| 集合可读 | ✅ `listPrivacyRequests` 返回 `success:true`（此前是 `-502005`） |
| 页面状态 | ✅ `requestsLoaded: true`（此前恒为 `false`） |
| 提交 | ✅ 页面显示「申请已提交，尚未完成处理……」 |
| 真正落库 | ✅ 云端回读到 `requestType: 查阅/复制`、`status: received` |

**注意：验证过程中写入了一条真实的测试申请，需要手工删除。**

```
集合：privacy_requests
_id：privacy-7c1ab5917cd4b5af986ce995173549e402037d9a8faaa714b6f0bc734b4d0890
requestType：查阅/复制
details：内测冒烟测试数据，验证完请删除
```

在云开发控制台 → 云数据库 → `privacy_requests` → 找到该行 → 删除即可。

用你自己的工作微信扫码进体验版，按下面走一遍，**预计 3 分钟**：

```
□ 欢迎页同意 → 能进项目列表

□ 报告首屏出现「需要优先处理」（若问题都不是一般）
□ 点「查看」→ 跳到对应照片
□ 我的 → 隐私与服务说明 → 提交一个申请 → 状态显示「已受理，待核验」
```

最后一条是新增的，**务必真提交一次**——它依赖步骤 4。

## 内测期间必须有人在

内测用户如果提交了**注销账号 / 删除个人信息**的申请，你要真的处理。

现在这套只有「收件箱」：申请落库、状态可查，但**没有任何自动删除**。
你要去云开发控制台看 `privacy_requests`，按申请逐项处理并回填 `status` / `response`。

内测人少，手工处理是可以接受的——**但不能收了不办**。

## 两件会让内测体验变差的事

| 事项 | 影响 |
|---|---|
| **腾讯云密钥未轮换** | 一直挂着。内测会真实调用 ASR 与 AI |
| **AI 额度** | 之前 402 过。额度不足时用户点「AI 识图」直接失败，而这是卖点 |

建议拉人之前先确认额度，或用一两次真实调用验证通了再发。

## 内测收尾后再做正式上线

内测跑顺了，再走审核 → 发布。届时需要的是**另一份**清单：
服务类目、隐私指引、提审路径、审核版本号——那些属于公众平台侧，
按平台当前要求核对。

## 出问题时怎么回退

- **客户端**：重新上传上一版并设为体验版即可（`v1.0.11` 的源码不可重建，
  所以回退要用内测期间你自己留的包）。
- **云函数**：部署前先在控制台下载现有源码做备份，回退时上传旧包。
  这也是 `output/release-20261001-KEjM0A/` 那批备份的用途。

> 从这一版起，每次上传前请先 `git tag`，别再出现「上线跑的是哪一版说不清」。
> 规则见 [发布流程](发布流程.md)。
